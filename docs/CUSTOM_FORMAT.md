# 客製文字格式：STAT-01

應用程式版本仍為 v3.8.0。此變更只擴充既有 `orders.custom TEXT` 的內容表示；SQLite 欄位、4.1 備份外層、Fernet 與 GitHub 同步協定不變。

## 新訂單

前綴為 `@OfficeEats.Custom/v1:`，後接 canonical JSON（UTF-8 字元、key 排序、無額外空白）。欄位必須恰為：

- `v`：整數 1。
- `category`：主餐或飲料，必須符合訂單類別。
- `fixed`：主餐依序為尺寸、辣度；飲料依序為尺寸、甜度、冰塊。空欄位用空字串保留位置。
- `tags`：快速客製文字清單，保留原順序及重複項。
- `manual`：手動文字，保留欄位來源及文字內容。

解析器拒絕重複 JSON keys、額外欄位、不正確型別、版本、類別、欄位數及非 canonical 表示。未辨識或損毀內容以原文字保留，不執行、不猜測、不自動升級。

## 統計與畫面

新格式分組鍵依序為類別、固定欄位 tuple、自由項目 tuple；餐點名稱仍是既有外層分組鍵。自由項目來自 tags 與 manual，只沿用半形逗號拆項、去除項目前後空白、以 Unicode 固定排序；不使用 set，不刪除重複項。

全形逗號、斜線及其他內部標點不是現有自由項目分隔符，保持原意。尺寸、辣度、甜度、冰塊不參與自由項目排序。統計標籤明示欄位與「客製」，避免固定小辣與手動小辣顯示混淆。個人訂單、統計明細與收款保留自由文字原始項目次序；不向使用者顯示編碼。

空客製與有客製分開，原有總數、總額及「部分有客製才補無客製」規則不變。

## 歷史資料

不批次遷移、不將舊文字標準化寫回 SQLite。歷史文字使用獨立 legacy 分組鍵；不與來源明確的新格式合併，也不因調整目前選項而重分類。

舊主餐無法還原固定欄位來源：統計以「歷史」標示原文字，編輯提供完整歷史文字欄位，不自動補入尺寸／辣度。舊飲料沿用斜線位置格式，保留空欄位及停用選項；純文字不依目前選項名稱補綁尺寸。只修改名稱、單價、數量時，舊客製原字串保持不變；明確編輯舊客製仍儲存為舊文字，不假冒已知來源。

停用的新格式固定值／快速客製只加入該筆編輯選單；不改全域選項。保留仍被選取之重複 tag 的數量。

## 切換前與回復限制

- 本 PR 不執行正式資料查詢、遷移或部署。合併／部署前，負責人須唯讀確認現存歷史資料沒有恰好符合完整 canonical v1 envelope 的原始文字。僅有前綴或看似 JSON 不會被當成 v1。
- 任意自由文字理論上可以與完整合法 envelope 完全相同；單一 TEXT 欄位不可能從相同 bytes 還原來源。若確認存在此類碰撞，停止切換，另行核准避免歧義的儲存方案，不自動改寫那些歷史訂單。
- 新版能讀取舊版資料；不代表舊應用能安全編輯新版 envelope。啟用後不可讓不支援 v1 的舊程式繼續寫入。
- 切換前另存經驗證的 JSON／加密備份與安全狀態；不覆寫未驗證備份。
- 若需回復，先停止寫入並保留包含新格式的完整資料。優先回復至仍保留 codec 的相容程式；不可直接以舊備份覆蓋目前資料。轉成舊文字會喪失欄位來源，必須另行核准、隔離驗證後才可處理。
- 沒有 schema migration，也沒有自動回填。正式環境內容與上述碰撞檢查尚未驗證。
